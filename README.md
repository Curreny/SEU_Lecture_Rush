# SEU Lecture Reserve（Requests版）

东南大学人文与科学素养系列讲座预约脚本。以 `lecture_request.py` 为主要入口，通过 HTTP 接口完成认证、预约资格检查、图形验证码识别和定时提交，无需启动浏览器。

仓库同时保留 Selenium 版本 `lecture_selenum.py`，用于通过网页扫描和筛选讲座。两个脚本独立运行，本文主要介绍 Requests 版本。

## 功能概览

- **指定讲座**：通过 `WID` 锁定一场讲座，持续尝试预约。
- **会话复用**：使用同一个 `requests.Session` 完成 CAS、VPN 和讲座系统认证，保留各阶段 Cookie。
- **自动识别验证码**：复用 `ddddocr` 识别器，每轮获取新验证码，仅接受四位数字的识别结果。
- **定时提交**：只有本机时间晚于 `start_time` 时，才调用提交预约接口。
- **结果反馈**：打印每轮资格检查和提交响应，接口返回成功后结束；支持 `Ctrl+C` 停止。

## 快速开始

### 1. 安装依赖

项目使用 Python 3.12，依赖声明在 `pyproject.toml`，版本锁定在 `uv.lock`。在项目根目录运行：

```bash
uv sync --locked
```

Requests 版本无需 Chrome 或 ChromeDriver；项目公共依赖中仍包含 Selenium，供浏览器版本使用。

### 2. 配置账号和讲座

将 `.env.example` 复制为项目根目录下的 `.env`，填写：

```dotenv
WID=目标讲座的WID
username=你的一卡通号
password='你的统一身份认证密码'
```

| 配置项 | 含义 |
| --- | --- |
| `WID` | 讲座唯一标识，不是讲座名称 |
| `username` | 统一身份认证账号，按字符串读取 |
| `password` | 统一身份认证密码，按字符串读取 |

`WID` 可从目标讲座在网页上的预约相关请求中查看：打开浏览器开发者工具的 Network 面板，查看 `appiontCheck.do` 请求的 `wid` 参数。脚本不会自动查询讲座列表或推断 `WID`。


### 3. 设置预约开始时间

修改 `lecture_request.py` 顶部的配置：

```python
# 示例日期，请替换为目标讲座实际开放预约的时间。
start_time = datetime(2026, 10, 26, 12, 26, 15)

# 每轮处理结束后的额外等待秒数，0 表示不增加等待。
POLL_INTERVAL = 0
```

`datetime()` 的参数依次为年、月、日、时、分、秒，均为整数。脚本使用本机本地时间，不自动转换时区；按北京时间预约时，请确保系统时区与时间正确。

**开始时间只限制提交，不限制资格检查和验证码请求。** 提前启动后，脚本会先认证并进入轮询；资格检查通过时，即使尚未到点，也会获取、识别并保存验证码。只有执行到 `datetime.now() > start_time` 且条件成立时才提交，并不保证在设定时刻精确发出请求。若设定时间已经过去，满足其他条件后会立即尝试提交。

### 4. 启动

```bash
uv run --locked python lecture_request.py
```

运行环境需要能够访问学校认证、VPN 和讲座系统。默认运行会实际提交预约；可以先只验证登录和会话复用：

```bash
uv run --locked python lecture_request.py --auth-only
```

该选项会检查登录、必要时发送短信并提示输入验证码，但不会提交预约。脚本没有 `--once`、`--interval` 选项。

## 工作流程

### 认证阶段

全程沿用一个 `requests.Session`：

1. **恢复会话**：从项目目录的 `.auth_state/` 恢复当前账号的设备标识、User-Agent、Cookie 和 CAS `tgtCookie`。先只读查询讲座列表并确认个人信息；已有会话有效时直接使用。
2. **CAS 登录**：业务会话失效时，先尝试 `casLoginByCookie` 换取新的回调。如果保存的 CAS 凭据也失效，或该恢复接口返回 `404/405/410`，则保留设备标识和设备信任 Cookie，获取 RSA 公钥，使用 PKCS#1 v1.5 填充加密密码，调用 `casLogin`。接口不可用不代表 Cookie 过期。遇到业务码 `502` 时发送短信并提示手动输入六位验证码，再获取公钥，分别加密密码和短信验证码提交，并申请记住此设备。
3. **VPN 认证**：访问登录回调，获取 CSRF Token；按服务端要求上报浏览器环境，再调用 `authCheck`。重启后复用同一个 VPN 设备标识。
4. **业务会话建立**：跟随讲座入口的验证跳转，通过 `verifyTgt` 获取新的业务 Ticket，再访问回调地址接收业务 Cookie。确认能取得个人讲座信息后保存状态。
5. **进入预约循环**：认证结束后持续处理 `.env` 指定的 `WID`；`--auth-only` 模式到此退出。

首次运行通常仍需短信验证。脚本为自己生成并持久保存设备标识，不会自动继承你已有浏览器的信任。服务端是否接受该标识、设备信任和会话何时过期，以实际认证结果为准；有效期内可复用，服务端再次要求验证时仍需手动输入短信。

`.auth_state/` 按账号分文件保存，已加入 `.gitignore`，新建缓存文件权限为 `0600`。缓存包含可用于登录的凭据，请勿分享；其中不保存密码、短信验证码或 RSA 密文，也不重放旧的业务 ST。保留该目录才能在重启后继续使用同一设备身份。删除对应缓存文件会同时清除本地会话和设备身份，下次可能需要重新短信验证。
